# Архитектура jupyter-cleaner

Документ описывает текущую реализацию конвертера: от чтения JSON-файла Jupyter
Notebook до записи Markdown и сбора статистики. Здесь зафиксированы только те
объекты и связи, которые присутствуют в коде.

## 1. Назначение модулей

| Модуль | Ответственность |
| --- | --- |
| `converter.py` | Ядро преобразования: читает notebook из JSON, оркестрирует преобразование ячеек и собирает итоговый текст со статистикой. Функция `convert_notebook()` сохраняет функциональный интерфейс поверх `NotebookConverter`. |
| `cli.py` | Typer-приложение: принимает аргументы, запускает ядро, сохраняет `.md`, печатает статистику и превращает ожидаемые ошибки в понятные сообщения. |
| `models.py` | Содержит модели результата одного преобразования: изменяемую статистику `ConversionStats` и объединяющий текст со статистикой `ConversionResult`. |
| `cells.py` | Описывает базовую ячейку и преобразование Markdown- и code-ячеек. `CodeCell` формирует блок Python и делегирует обработку результатов выполнения. |
| `outputs.py` | Извлекает `text/plain`, `text/html` и stream-вывод из структур Jupyter, учитывает outputs в статистике, применяет настройки и формирует Markdown для поддерживаемых результатов. |
| `tables.py` | Распознаёт ограниченный поддерживаемый формат HTML-таблиц Pandas и преобразует его в Markdown-таблицу; неподдерживаемую разметку отвергает. |
| `config.py` | Определяет неизменяемую конфигурацию одного преобразования: сохранение outputs, удаление пустых ячеек и преобразование таблиц. |
| `exceptions.py` | Определяет доменную иерархию ошибок загрузки notebook: общий `NotebookError`, отсутствие файла и некорректный JSON. |

## 2. Основные объекты

### `NotebookConverter`

- **Ответственность:** управляет одним проходом по `notebook["cells"]`, создаёт
  нужные объекты ячеек, пропускает неподдерживаемые типы, применяет правило для
  пустых ячеек и собирает общий Markdown и статистику.
- **Основные входные данные:** `ConversionConfig` в конструкторе и словарь
  notebook в `convert()`.
- **Основной результат:** `ConversionResult`.
- **Взаимодействует с:** `ConversionConfig`, `ConversionStats`, `MarkdownCell`,
  `CodeCell`, одним общим экземпляром `OutputProcessor` и `ConversionResult`.

### `ConversionConfig`

- **Ответственность:** хранит неизменяемые параметры одного запуска.
- **Основные входные данные:** булевы `keep_outputs` (по умолчанию `False`),
  `remove_empty_cells` и `convert_tables` (оба по умолчанию `True`).
- **Основной результат:** готовое значение конфигурации; самостоятельного
  преобразования класс не выполняет.
- **Взаимодействует с:** `NotebookConverter`, `CodeCell`, `OutputProcessor` и
  функцией `convert_output()`.

### `ConversionResult`

- **Ответственность:** объединяет результат преобразования и сведения о нём.
- **Основные входные данные:** строка `markdown_text` и `ConversionStats` (при
  отсутствии статистики создаётся отдельный экземпляр со значениями по умолчанию).
- **Основной результат:** объект, из которого вызывающий код получает Markdown и
  статистику.
- **Взаимодействует с:** создаётся `NotebookConverter`; в CLI его текст передаётся
  `save_markdown()`, а статистика — функциям вывода и расчёта размеров.

### `ConversionStats`

- **Ответственность:** хранит счётчики ячеек, outputs и таблиц, а также размеры
  входного и выходного файлов и процент изменения размера.
- **Основные входные данные:** начальные значения полей (обычно используются
  нули); во время конвертации тот же объект явно передаётся обработчикам.
- **Основной результат:** накопленная статистика одного запуска.
- **Взаимодействует с:** `NotebookConverter`, `CodeCell`, `OutputProcessor`,
  `convert_output()`, `add_file_size_stats()` и функциями печати статистики.

### `Cell`

- **Ответственность:** задаёт общее представление ячейки, хранит `source` и
  реализует общую проверку `is_empty()`.
- **Основные входные данные:** объединённый в строку исходный текст ячейки.
- **Основной результат:** базовый класс сам не конвертирует данные — `convert()`
  требует реализации наследника.
- **Взаимодействует с:** служит родителем `MarkdownCell` и `CodeCell`.

### `MarkdownCell`

- **Ответственность:** представляет Markdown-ячейку.
- **Основные входные данные:** строка исходного Markdown.
- **Основной результат:** исходная строка без дополнительного оформления.
- **Взаимодействует с:** наследует `Cell`, создаётся и вызывается
  `NotebookConverter`.

### `CodeCell`

- **Ответственность:** представляет кодовую ячейку, оформляет source как fenced
  block `python` и при необходимости добавляет обработанные outputs.
- **Основные входные данные:** строка кода, последовательность словарей outputs и
  `OutputProcessor`; в `convert()` — конфигурация и необязательная статистика.
  Коллекция outputs сохраняется как кортеж и при преобразовании только читается.
- **Основной результат:** Markdown-фрагмент кодовой ячейки.
- **Взаимодействует с:** наследует `Cell`, создаётся `NotebookConverter`, передаёт
  outputs, конфигурацию и статистику в `OutputProcessor`.

### `OutputProcessor`

- **Ответственность:** учитывает outputs, соблюдает `keep_outputs`, преобразует
  каждый поддерживаемый результат и объединяет полученные фрагменты.
- **Основные входные данные:** последовательность словарей Jupyter output,
  `ConversionConfig` и необязательный `ConversionStats`.
- **Основной результат:** строка Markdown с результатами либо пустая строка.
- **Взаимодействует с:** вызывается `CodeCell`, использует функции извлечения и
  `convert_output()` из `outputs.py`, владеет `TableConverter`. Один экземпляр
  процессора создаётся `NotebookConverter` и передаётся всем code-ячейкам.

### `TableConverter`

- **Ответственность:** проверяет строгую структуру HTML-таблицы Pandas и строит
  Markdown-таблицу, декодируя HTML-сущности, нормализуя переносы и экранируя `|`.
- **Основные входные данные:** строка HTML.
- **Основной результат:** строка Markdown для поддерживаемой таблицы или `None`.
- **Взаимодействует с:** принадлежит `OutputProcessor` и вызывается через
  `convert_output()`; напрямую от notebook и CLI не зависит.

## 3. Схема объектов

Стрелка вниз означает создание или использование объекта, а `is a` —
наследование.

```text
NotebookConverter
        ├── хранит ConversionConfig
        ├── создаёт ConversionStats
        ├── создаёт MarkdownCell ──is a──> Cell
        ├── создаёт CodeCell ──────is a──> Cell
        │          └── использует OutputProcessor (переданный конвертером)
        │                         └── хранит TableConverter
        └── возвращает ConversionResult
                              └── хранит ConversionStats
```

`ConversionStats` — один явно передаваемый объект на один вызов `convert()`.
`CodeCell` не хранит собственную скрытую статистику. Обработка таблицы достижима
только при обработке output, когда включены `keep_outputs` и `convert_tables`, а
`text/html` распознан как поддерживаемая таблица Pandas.

## 4. Поток данных

Файловые операции находятся вокруг ядра преобразования, а не внутри метода
`NotebookConverter.convert()`:

```text
.ipynb
   ↓
load_notebook(file_path)
   ↓ json.load()
словарь notebook
   ↓
NotebookConverter.convert(notebook)
   ↓ создаёт по поддерживаемым элементам notebook["cells"]
MarkdownCell / CodeCell
   ↓ Cell.convert(...)
Markdown-фрагменты
   ↓ объединение через пустую строку
ConversionResult(markdown_text, stats)
   ↓ result.markdown_text
save_markdown(markdown_text, output_path)
   ↓
.md
```

`raw` и любые типы ячеек, кроме `markdown` и `code`, не создают объект `Cell` и
не входят в итоговый текст, хотя входят в `cells_total`. Если включено удаление
пустых ячеек, пустая поддерживаемая ячейка также не создаёт фрагмент.

## 5. Пример прохождения кодовой ячейки

````text
словарь с cell_type="code", source и outputs
        ↓ NotebookConverter объединяет элементы source
CodeCell(source, outputs, общий OutputProcessor)
        ↓ CodeCell.convert(config, stats)
fenced-блок ```python с исходным кодом
        ↓ OutputProcessor.process(outputs, config, stats)
учёт количества outputs
        ├── keep_outputs=False → пустая строка
        └── keep_outputs=True → обработка каждого output
                                  ↓
                     stream или text/plain → блок ```text
                                  │
                     поддерживаемый text/html и
                     convert_tables=True
                                  ↓
                           TableConverter
                                  ↓
                         Markdown-таблица
        ↓
блок Python и непустые outputs объединяются через пустую строку
        ↓
готовый Markdown-фрагмент CodeCell
````

Для `execute_result` и `display_data` поддерживаемая HTML-таблица имеет приоритет
над `text/plain`. Неподдерживаемый HTML сам по себе в результат не попадает: при
наличии используется `text/plain`, иначе output даёт пустой фрагмент. Stream
берётся из поля `text`.

Пустая code-ячейка при включённом `remove_empty_cells` не вызывает обычный
`process()`, но `NotebookConverter` отдельно вызывает `count_outputs()`, поэтому
её outputs учитываются в статистике и не сохраняются.

## 6. Принципы архитектуры

### Одна ответственность

Предметная логика разделена по модулям: настройки, модели результата, ячейки,
outputs, таблицы и ошибки загрузки находятся отдельно. `converter.py` остаётся
композиционным модулем ядра, а файловый вывод и взаимодействие с
терминалом вынесены в отдельный модуль `cli.py`.

### Композиция

`NotebookConverter` не копирует алгоритмы ячеек и outputs: он создаёт
`MarkdownCell`/`CodeCell` и передаёт code-ячейкам принадлежащий ему
`OutputProcessor`. Тот, в свою очередь, использует принадлежащий ему
`TableConverter`. Конструкторы `CodeCell` и `OutputProcessor` также допускают
явную подмену процессора или конвертера таблиц.

### Наследование

`MarkdownCell` и `CodeCell` — разные виды `Cell`. Они наследуют хранение source и
проверку пустоты, но реализуют `convert()` по-разному. Базовый `Cell.convert()`
намеренно поднимает `NotImplementedError`.

### Инкапсуляция

Вызывающему `NotebookConverter` не требуется знать, как оформляется code-блок,
разбирается MIME-словарь output или проверяется HTML Pandas. Эти решения скрыты
за `Cell.convert()`, `OutputProcessor.process()` и методами `TableConverter`.

### Явная передача данных

Конфигурация передаётся объектам явно, статистика создаётся для конкретного
вызова `NotebookConverter.convert()` и явно проходит в `CodeCell` и
`OutputProcessor`. Модули не используют изменяемое глобальное состояние; входной
словарь notebook и конфигурация при преобразовании не изменяются.

### Независимость ядра

`Cell`, `OutputProcessor`, `TableConverter`, модели и конфигурация не читают
аргументы командной строки и не выполняют файловый ввод-вывод. CLI находится в
Typer-приложение `cli.app`: оно загружает файл, запускает ядро, сохраняет результат и
печатает статистику. Поэтому ядро можно вызывать программно через
`NotebookConverter.convert()` или `convert_notebook()`.
